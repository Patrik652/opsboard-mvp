## 5. Pencil `.pen` fallback evaluation

Question: can a `.pen` file live in repo, sync tokens, and generate/update one component?

**Assessment: viable, but not installed in this POC (requires auth/extension install → ask Patrik first).**

- `.pen` files are git-native JSON design files designed to sit **alongside source code** in the repo and be version-controlled with normal git flow. ✔ compatible with "source of truth = code + tokens".
- Pencil syncs **design tokens** bidirectionally (token defs ↔ CSS vars), so opsboard's `globals.css` `:root` vars are a valid token surface. ✔
- Pencil's IDE extension (Cursor / VS Code / Claude Code, via MCP) can **generate/update a component** from a `.pen` node. ✔ in principle.
- **Cost:** requires installing the Pencil extension and an account/login. Per constraints (no global installs, stop on auth) this was **not executed**. Decision needed from Patrik.

Net: Pencil is the cleanest way to restore a *visual canvas* leg of Path A **without** a paid Figma seat, because the canvas lives in-repo as `.pen` and the tokens stay the single source of truth.

## 6. The one tiny change (token drift fix)

**Finding:** `page.tsx` defined a hardcoded palette (`bg-zinc-950 text-zinc-100`) while `globals.css` exposes design tokens (`--background`, `--foreground`) via `@theme inline`. Classic **token drift** — the rendered page bypassed the source of truth.

**Edit** (`src/app/page.tsx`, 1 line):
```diff
-    <div className="min-h-screen bg-zinc-950 text-zinc-100">
+    <div className="min-h-screen bg-background text-foreground">
```
Uses existing tokens only. No new design system. No new classes invented (`bg-background`/`text-foreground` are generated by the existing `@theme inline` mapping).

# Phase 2 — Productize Path A (2026-06-19)

Goal: make the code + tokens + Playwright loop **repeatable** as a committed guardrail. Decisions: keep the `page.tsx` token fix, no Figma seat upgrade, no Pencil install, no deploy.

## Scripts added (Playwright built-in `toHaveScreenshot`, zero new deps)

| Command | Purpose |
|---|---|
| `npm run verify:visual` | Compare current UI vs committed baselines; **fails** when > 1% of pixels differ beyond per-pixel threshold. |
| `npm run verify:visual:update` | Regenerate baselines from current token-correct UI. |

- Config: `playwright.visual.config.ts` — isolated from existing `playwright.config.ts` (own `testDir ./tests/visual`, port `3302`, `deviceScaleFactor 1`, `maxDiffPixelRatio 0.01`, `threshold 0.2`, auto `webServer` = `npm run dev`).
- Spec: `tests/visual/home.visual.spec.ts` — `/` at desktop `1440x900` + mobile `390x844`, `fullPage`, Next dev overlay hidden via `tests/visual/screenshot.css`.
- **Baselines (committed):** `tests/visual/__screenshots__/home-desktop.png`, `tests/visual/__screenshots__/home-mobile.png`. Regenerated once from current UI (the phase-1 MCP PNGs use a different capture pipeline/scale, so they are not byte-compatible with `toHaveScreenshot` and were not reused).
- Diff artifacts on failure (gitignored `test-results/`): `…/home-<v>-actual.png`, `…-expected.png`, `…-diff.png` — paths printed by the runner.

## Token-drift changes (small, existing tokens only)

Only **root page-shell** background/foreground swapped to the two existing token utilities (`bg-background`, `text-foreground` from `@theme inline`). Component-level surfaces (inputs, cards, sidebar, topbar fills using `bg-zinc-950`) were **left as-is** — they need `--panel`/`--input`/`--border` tokens that don't exist yet; inventing them was out of scope (no `globals.css` token-def rewrite).

| File | Change |
|---|---|
| `src/app/page.tsx` (phase 1, kept) | `bg-zinc-950 text-zinc-100` → `bg-background text-foreground` |
| `src/app/(app)/layout.tsx` | shell root `bg-zinc-950 text-zinc-100` → `bg-background text-foreground`; `<main>` `bg-zinc-950` → `bg-background` |

Remaining hardcoded primitives (≈200 zinc/emerald usages) are tracked as future work — they require a real token-system expansion, not a blind find/replace.
