# Design guardrail (Path A) — runbook

This project keeps human and AI UI edits honest with a **code + tokens + visual
regression** loop. There is no separate design tool: the rendered app *is* the
design, and a Playwright screenshot suite proves it didn't drift.

## Source of truth

1. **Code** — the React/Tailwind components under `src/`.
2. **Semantic tokens** — `src/app/globals.css` `@theme inline`. Components use
   role tokens, not raw palette shades:
   - surfaces: `bg-panel`, `bg-panel-muted`
   - borders: `border-border`, `border-border-strong`
   - brand: `text-accent`, `bg-accent`, `text-accent-foreground`
   - data state: `text-success`/`-soft`, `text-warning`, `text-danger`,
     `text-critical` (+ `*-muted` bg/border bases)
   - text scale: `text-text-primary` / `-body` / `-secondary` / `-muted` /
     `-subtle`
3. **Visual baselines** — committed PNGs in
   `tests/visual/__screenshots__/<route>-<viewport>.png`, generated by
   `tests/visual/routes.visual.spec.ts`.

The three move together. A token change that is a true alias must not change any
baseline; a baseline change must be a conscious visual decision.

## Run the checks locally

```bash
cd opsboard
npm run lint            # eslint
npm run build           # next build
npm run verify:visual   # Playwright screenshots vs committed baselines
npm test -- --run       # vitest unit tests
# or all four at once:
npm run verify
```

`verify:visual` auto-starts the dev server (Playwright `webServer`) on port
3302, screenshots `/`, `/boards`, `/incidents`, `/status`, `/analytics`,
`/ai`, `/operations`, `/audit` at desktop `1440x900` + mobile `390x844`
(fullPage), and fails if any screenshot differs by more than
`maxDiffPixelRatio: 0.01`. It also fails on any browser `pageerror` or
`console.error`.

On failure, Playwright writes `test-results/<test>/{...-actual,-expected,-diff}.png`
and prints those paths.

## Update baselines intentionally

Only when a visual change is **deliberate** (a real redesign, copy change, new
component):

```bash
cd opsboard
npm run verify:visual:update   # rewrites baselines from current UI
git add tests/visual/__screenshots__
```

Rules:
- Review the regenerated PNGs in the diff before committing — confirm every
  pixel change is intended.
- Note the visual change in the commit message (and in
  `docs/plans/2026-06-19-ai-design-workflow-poc.md` if it is part of the
  ongoing migration record).
- An **exact-alias token change must produce 0 pixel diff** — if
  `verify:visual:update` rewrites baselines after an "alias" change, the alias
  was wrong (different shade). Fix the mapping instead of updating baselines.

## Add a new route to the visual matrix

1. Open `tests/visual/routes.visual.spec.ts`.
2. Add `{ name, path, heading }` to the `routes` array. `heading` must match a
   real heading on the page (the test waits for it before snapshotting, so it
   captures loaded state, not a loading skeleton).
3. Confirm the route is **deterministic** — no live timestamps, random IDs, or
   loading races. Use the static demo seed; route timestamps through
   `src/lib/formatDateTime.ts` (`formatTimestamp`, fixed `en-GB` + UTC). If a
   route can't be made deterministic cleanly, leave it out and say why in a
   code comment.
4. `npm run verify:visual:update` to create the new baselines, review them,
   commit.

## Token change rules

- **Exact alias → 0 pixel diff.** New semantic tokens should alias the exact
  primitive already in use (`--color-x: var(--color-zinc-900)`), so migrating
  utilities changes nothing visually. `verify:visual` must stay green with
  baselines untouched.
- **Visual redesign → conscious baseline update + note.** Changing a token's
  value (real color change) is a redesign; regenerate baselines deliberately
  and document it.
- **Never loosen the threshold to hide a diff.** `maxDiffPixelRatio` /
  `threshold` in `playwright.visual.config.ts` are guardrails, not knobs to
  silence regressions. If a legitimate small diff appears, fix the cause or do
  a reviewed baseline update — do not raise the threshold.
- Do not introduce raw palette classes (`zinc-*`, `emerald-*`, …) for surfaces,
  borders, accent, data-state, or the text scale — use the role token. A few
  deliberate one-offs remain (yellow caution, rose inline error, the brand CTA)
  and are documented in the Phase 4B/5A notes.

## CI enforcement

`.github/workflows/opsboard-design-guardrail.yml` runs the same four checks on
every PR and on push to `main` that touches `opsboard/**`. It runs inside the
pinned Playwright container (`mcr.microsoft.com/playwright:v1.58.0-noble`) so
the browser/fonts match the baseline environment, and uploads the
diff/actual/expected images as an artifact when the visual step fails.

> **Baseline environment note (validated 2026-06-19).** `toHaveScreenshot`
> baselines are environment-sensitive. Two things were needed to make them
> portable to CI:
>
> 1. **Self-hosted fonts.** Fonts are loaded with `next/font` (baked into the
>    build), not a runtime Google Fonts CDN `@import`. The CDN rendered
>    non-deterministically across environments and caused console errors and a
>    `networkidle` hang. **Do not reintroduce a CDN `@import` for fonts.**
> 2. **Runner-generated baselines.** Even inside the same pinned container,
>    sub-pixel font rasterization differs between a developer machine and the
>    GitHub runner. In practice 15/16 baselines are byte-identical across
>    machines; only `home-mobile` (dense hero text at the smallest viewport)
>    differs (~3%). So **`home-mobile.png` is committed from the runner**, and
>    **CI is the canonical baseline environment**.
>
> **Local visual runs may diff on `home-mobile`** — that's expected; trust CI
> for that one screenshot. To realign baselines after an intentional UI change:
> push the branch, let the guardrail run, and if the visual step fails it
> regenerates baselines on the runner and uploads them as the
> `opsboard-runner-baselines` artifact. Download that artifact, copy the PNGs
> into `tests/visual/__screenshots__/`, review the diff, and commit. **Never**
> raise the threshold to absorb a diff.
